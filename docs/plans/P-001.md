# P-001 — Research Register 및 업데이트 거버넌스 부트스트랩

## Outcome

- **목표 결과:** 이후 조사마다 상세 Markdown 보고서를 누적하고, 별도 주제는 새 R-ID로 분리하며, 업데이트 계획과 실행이 관련 연구를 반드시 추적하는 저장소 내 시스템을 구축한다.
- **사용자 가치:** 새 세션에서도 과거 근거와 미해결 위험을 잃지 않고, 조사와 실제 코드 변경 사이의 논리적 연결을 검토할 수 있다.
- **완료 정의:** R/P/E 문서 계층, 생성·동기화·검증 명령, CI 게이트, PR 체크리스트, 완성된 기준 사례가 존재하고 로컬 검사가 통과한다.

## Requirements and non-goals

### 요구사항

- 저장소 전역에서 적용되는 필수 Research → Plan → Execution → Verification 규칙을 둔다.
- 같은 R-ID 갱신과 새 R-ID 생성의 경계를 의사결정 단위로 정의한다.
- 상세 보고서가 사실·추론·권고와 출처를 분리하도록 템플릿을 제공한다.
- R/P/E 생성기는 ID를 중복 없이 발급하고 참조를 자동 승계한다.
- 검증기는 frontmatter, ID, 상태, 필수 섹션, Register parity, 링크, R→P→E 참조를 검사한다.
- CI는 제품·운영 파일 변경에 같은 변경 세트의 실행 기록이 있는지 검사한다.
- 이번 부트스트랩을 R-001/P-001/E-001로 자체 기록한다.

### 비범위

- 기존 제품 동작 수정
- 깨진 native acceptance 엔트리포인트 복원
- 버전 파일 동기화 정책 수정
- 외부 프로젝트 관리 도구 도입
- GitHub 저장소 설정에서 branch protection을 직접 변경

1. AGENTS와 R/P/E 운영 문서, 템플릿, R-001/P-001을 먼저 추가한다.
2. Node 표준 라이브러리만 사용하는 생성·검증 스크립트를 구현한다.
3. package script와 GitHub workflow, PR 템플릿, README 진입점을 연결한다.
4. E-001에 실제 변경과 검증 결과를 기록한다.
5. `research:sync`, `governance:check`, 생성기 dry-run, typecheck를 순서대로 실행한다.
6. diff를 독립 리뷰하고 발견 사항을 반영한 뒤 P-001/E-001을 완료 상태로 바꾼다.

## Documentation and release impact

- **README/사용자 문서:** Building from source 아래에 Maintainer workflow 링크만 추가한다.
- **manifest/package/versions:** package script만 추가한다. 버전 값과 Obsidian 호환성은 변경하지 않는다.
- **`main.js` 재생성:** 하지 않는다. 런타임 소스 변경이 없다.
- **릴리스·마이그레이션:** 사용자 릴리스가 아니라 개발 프로세스 변경이다. 데이터 마이그레이션은 없다.
