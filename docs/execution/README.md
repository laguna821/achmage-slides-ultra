# Execution Records

실행 기록은 계획의 약속과 실제 저장소 변경 사이의 차이를 보존한다. 로그 덤프가 아니라 재현 가능한 명령, 핵심 결과, 변경 경로, 계획 이탈, 남은 위험을 담는다.

## 생성

계획을 `approved`로 바꾼 뒤 실행 기록을 만든다.

```bash
npm run execution:new -- --title "내보내기 실패 처리 구현" --plan P-002
```

생성기는 계획의 `research` 목록을 실행 기록에 복사한다. 실행에서 R-ID를 제거하지 않는다. 새 연구가 필요해지면 보고서와 계획을 먼저 개정한 뒤 실행 기록에도 추가한다.

## 상태

- `in-progress`: 승인된 계획을 실행 중
- `blocked`: 외부 결정, 권한, 재현 불가 등으로 더 진행할 수 없음
- `complete`: 변경과 검증이 끝나고 결과가 기록됨
- `superseded`: 다른 E-ID로 대체됨

## 완료 기준

- 실제 변경 경로가 모두 Change map에 있다.
- 계획에서 벗어난 내용은 “없음”이라고 생략하지 말고, 없으면 명시적으로 없음이라고 적는다.
- 실행한 명령, 종료 코드, 핵심 수치 또는 관찰을 남긴다.
- 생성 산출물(`main.js` 등)은 생성 여부와 diff 검토 결과를 적는다.
- 계획의 모든 AC-ID를 중복이나 누락 없이 정확히 한 번 PASS/FAIL/BLOCKED로 연결한다. `complete`는 전부 PASS일 때만 허용한다.
- 실패나 남은 위험을 삭제하지 않고 후속 R/P/E 후보로 남긴다.
- `npm run governance:check -- --base HEAD`가 현재 변경 경로까지 포함해 통과한다.
- `npm run governance:smoke`가 생성과 주요 실패 게이트를 재현한다.

E-ID는 감사 기록이므로 완료·중단 후에도 삭제하거나 다른 실행에 재사용하지 않는다. 재실행이 독립적인 변경 세트라면 새 E-ID를 만든다.
