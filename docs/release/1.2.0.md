# Achmage Slides Ultra 1.2.0

## English

### One-click MP4 export

- Added **Export current note as MP4** to the command palette and **Export MP4** to Open Slide Preview.
- ASU reuses the same audited physical slides as Preview and HTML export, then creates a silent 1920×1080 H.264 MP4 at 30fps beside the source note.
- Choose one global hold time from 0.5 to 60.0 seconds per slide (default 3.0 seconds). Smart motion moves vertically between overflow slides in one section and horizontally across section boundaries.
- Encoding is local. It uses the WebCodecs implementation already provided by Obsidian's desktop runtime; no AI tokens, cloud renderer, Remotion runtime, FFmpeg installation, or separate sidecar is required.
- The exporter writes to a collision-safe `<note>.slides.mp4` name, never overwrites an existing video, supports cancellation, and verifies the completed MP4 before reporting success. Extremely long collision names are shortened with a stable stem hash. A full-file SHA-256 and size seal is checked before and after validation and again after publication. If initial identity cannot be established, or the operating system later rejects cleanup, ASU preserves the unknown path and reports the exact private partial path.

### Compatibility, privacy, and known limits

- MP4 export requires desktop Obsidian 1.13.4 or later, OffscreenCanvas, and an available H.264 encoder. If Obsidian is current but its bundled Electron runtime is older, close the app and install the current desktop installer over the existing installation. The exporter fails with an actionable message when the host cannot satisfy the codec contract; it does not silently switch formats or upload content.
- Remote images used by the rendered deck are fetched only from their referenced URLs and embedded before encoding. Missing or undecodable required assets stop the export instead of producing a silently incomplete video. Cancelling or timing out discards the result, although Obsidian's `requestUrl` cannot abort an HTTP request already started by the host. ASU itself performs no content upload, but a vault sync provider may upload the same-directory partial/final output and its deletion history under the provider's normal rules.
- Static PNG, JPEG, GIF, WebP, BMP, AVIF, SVG, and common MIME aliases are checked before decode. ICO is rejected because directory dimensions cannot conservatively bound every embedded PNG/DIB payload; convert it to static PNG before export. APNG, multi-frame GIF, animated WebP, and AVIF sequences fail explicitly because wall-clock raster animation is outside the deterministic 1.2.0 contract. Nested SVG namespace aliases, nested data fonts or external resources, fragment-only image/background reloads, authored CSS transitions or animations, and `@starting-style` also fail closed. Resource admission limits are 24 MiB per compressed asset, 64 MiB total compressed assets, 8192px/40 million pixels per image, 134,217,728 unique decoded pixels, and 48 Mi characters of serialized capture markup. Oversized or conservatively uninspectable images stop with a resize/format error instead of risking an unbounded decode.
- Version 1.2.0 exports silent MP4 only. It does not add audio, TTS, captions, embedded video/iframe/object capture, nested external assets inside an SVG image, element-level animation, a timeline editor, WebM/MOV/GIF, 4K, or custom codec/bitrate controls. Unsupported rendered media fails explicitly rather than being omitted.
- Output publication requires same-directory hard-link support. Existing videos are never overwritten, and the exporter does not use a rename/copy fallback when a filesystem or sync provider rejects that atomic operation. The private partial is identity-checked before cleanup, but Node has no conditional unlink-by-inode API; a local process or sync provider can still race the tiny interval between that check and path unlink. An external edit after the final content seal is an ordinary modification of the published file and is outside the completed export transaction.
- Parser, Pretext, overflow packing, navigation, settings schema, saved state, and HTML export remain compatible with 1.1.4. Normal Preview and HTML export do not retain the video artifact or initialize the video muxer path.
- The MP4 container path uses tree-shaken Mediabunny 1.52.3 under MPL-2.0. Source and license details are recorded in `THIRD_PARTY_NOTICES.md`. This release makes no loading-performance claim based on bundle size.

## 한국어

### 원클릭 MP4 내보내기

- 명령 팔레트에 **Export current note as MP4**, Open Slide Preview 도구 모음에 **Export MP4**를 추가했습니다.
- ASU가 Preview·HTML export와 같은 최종 검증 physical slide를 재사용해 원본 note 옆에 1920×1080, 30fps, 무음 H.264 MP4를 생성합니다.
- 전체 slide에 적용할 정지 시간을 0.5~60.0초에서 선택할 수 있고 기본값은 3.0초입니다. Smart motion은 같은 section의 overflow slide 사이에서는 세로로, section 경계에서는 가로로 움직입니다.
- 인코딩은 로컬에서 이루어집니다. Obsidian desktop runtime이 이미 제공하는 WebCodecs를 사용하므로 AI token, cloud renderer, Remotion runtime, 별도 FFmpeg 설치나 sidecar가 필요하지 않습니다.
- `<note>.slides.mp4`를 기준으로 충돌 없는 파일명을 선택하며 기존 영상을 덮어쓰지 않습니다. 충돌 suffix 때문에 파일명 한계를 넘는 아주 긴 note 이름은 full stem의 안정적인 hash를 붙여 줄입니다. 취소할 수 있고, validation 전후와 게시 뒤에 retained handle의 전체 파일 SHA-256·크기를 대조한 뒤에만 성공으로 표시합니다. 최초 identity를 확인할 수 없거나 운영체제가 cleanup을 거부하면 unknown path를 지우지 않고 해당 private partial의 정확한 경로를 알려 줍니다.

### 호환성·개인정보·알려진 제약

- MP4 export에는 desktop Obsidian 1.13.4 이상, OffscreenCanvas와 사용 가능한 H.264 encoder가 필요합니다. Obsidian 자체는 최신인데 내장 Electron runtime이 오래된 경우 앱을 완전히 종료한 뒤 최신 desktop installer를 기존 설치 위에 다시 설치하면 됩니다. host가 codec 계약을 만족하지 않으면 다른 형식이나 upload로 몰래 우회하지 않고 조치 가능한 오류를 표시합니다.
- 렌더된 deck에 필요한 remote image는 해당 참조 URL에서만 받아 encoding 전에 내장합니다. 필수 asset이 없거나 decode할 수 없으면 불완전한 영상을 조용히 만들지 않고 export를 중단합니다. Cancel 또는 timeout 뒤 ASU는 결과를 버리지만 Obsidian `requestUrl`은 host가 이미 시작한 HTTP request 자체를 중단할 수 없어 background에서 끝날 수 있습니다. ASU 자체는 내용을 upload하지 않지만 vault의 sync provider는 일반 동기화 규칙에 따라 같은 directory의 partial/final 파일과 삭제 이력을 upload할 수 있습니다.
- Static PNG, JPEG, GIF, WebP, BMP, AVIF, SVG와 common MIME alias를 decode 전에 검사합니다. ICO는 directory dimension만으로 모든 embedded PNG/DIB payload를 보수적으로 제한할 수 없어 거절하며, export 전에 static PNG로 변환해야 합니다. APNG, multi-frame GIF, animated WebP, AVIF sequence는 wall-clock raster animation이 1.2.0의 deterministic 계약 밖이므로 명시적으로 중단합니다. Nested SVG namespace alias·data font·external resource, fragment-only image/background reload, 작성된 CSS transition·animation과 `@starting-style`도 fail-closed합니다. 제한은 compressed asset 1개 24MiB·전체 64MiB, image 1개 축 8192px·4천만 pixels, unique decoded image 합계 134,217,728 pixels, serialized capture 48Mi characters입니다. 초과하거나 보수적으로 header를 검사할 수 없는 image는 무제한 decode 대신 resize/format 오류로 중단합니다.
- 1.2.0은 무음 MP4만 지원합니다. Audio, TTS, caption, embedded video/iframe/object capture, SVG image 내부의 nested external asset, element-level animation, timeline editor, WebM/MOV/GIF, 4K, custom codec/bitrate control은 포함하지 않습니다. 지원하지 않는 rendered media는 조용히 누락하지 않고 명시적으로 실패합니다.
- 최종 파일 게시에는 같은 directory의 hard-link 지원이 필요합니다. 기존 video는 덮어쓰지 않으며 filesystem 또는 sync provider가 원자적 link를 거부해도 rename/copy로 우회하지 않습니다. Private partial은 cleanup 직전에 identity를 검사하지만 Node에는 특정 inode일 때만 unlink하는 원자 API가 없으므로, local process 또는 sync provider가 최종 검사와 path unlink 사이의 아주 짧은 구간에 개입하는 OS-level race는 남습니다. 마지막 content seal 뒤 published file을 외부에서 편집하는 것은 완료된 export transaction 밖의 일반 파일 수정입니다.
- Parser, Pretext, overflow packing, navigation, 설정 schema, 저장 상태와 HTML export는 1.1.4와 호환됩니다. 일반 Preview와 HTML export는 video artifact를 보존하거나 video muxer 경로를 초기화하지 않습니다.
- MP4 container 경로는 MPL-2.0의 tree-shaken Mediabunny 1.52.3을 사용하며 source·license 정보는 `THIRD_PARTY_NOTICES.md`에 기록했습니다. Bundle byte 변화만으로 loading 성능 향상을 주장하지 않습니다.
